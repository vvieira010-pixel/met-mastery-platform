## Detailed Findings by Severity

### P1 — Major (fix before release)

**[P1] Undefined CSS custom properties (broken styles)**
- **Location:** `src/styles/components.css:1260, 1632, 1649, 1650, 4298, 4469` (+ deprecated ref at `:5504`)
- **Category:** Theming
- **Impact:** `var(--text-2sm)`, `var(--text-1)`, `var(--hover-bg)` are **never defined** in `tokens.css`. Affected elements (shell brand name, search input/clear, quick-action chips) silently fall back to inherited/initial values — wrong font sizes, missing hover background. The `:5504` comment even says "use --text-2sm token" while the token itself doesn't exist.
- **Recommendation:** Define the tokens in `tokens.css` (`--text-2sm: 0.6875rem;` etc.) **or** repoint each usage to existing tokens (`--text-2xs` / `--text-2`). Add a lint/CSS-var check to CI.
- **Suggested command:** `/normalize` (then `/polish`)

**[P1] Dark-mode contrast risk from per-component patching**
- **Location:** `src/styles/dark.css` (whole file), `src/App.tsx:244` (toggle wired ✓)
- **Category:** Accessibility / Theming
- **Impact:** `--primary` (#01796F) is used as a *foreground* color in dark mode and the file's own comment admits it rendered ~1.1:1 (effectively invisible). It was fixed only for an enumerated list of selectors (`.student-hero h1`, `.badge-primary`, …). Any component not in that list still gets invisible teal text on dark surfaces. WCAG AA (4.5:1) is **not guaranteed** for uncovered components.
- **Recommendation:** Stop using `--primary` as text color; introduce a dedicated `--text-accent` token that flips correctly in dark mode. Audit every `color: var(--primary)` / `--accent` text usage in dark for contrast ≥ 4.5:1. Add a contrast check (e.g. axe / Lighthouse) to CI.
- **Suggested command:** `/audit` (a11y) → `/normalize` (tokens) → `/polish`

### P2 — Minor (fix in next pass)

**[P2] `!important` fragility (47 occurrences)**
- **Location:** `src/styles/*` (mostly `dark.css`, `responsive.css`)
- **Category:** Theming
- **Impact:** `47` `!important` rules — e.g. `[data-theme="dark"] .td-priority-card { background: var(--surface) !important; }`, `.role-btn:hover * { color:#fff !important; }`, `.td-student-card { aspect-ratio:auto !important; … }`. These fight specificity and make future theming changes brittle; a single missed patch silently breaks.
- **Recommendation:** Replace with higher-specificity selectors or token flips. Reserve `!important` for true overrides (e.g. `prefers-reduced-motion`).
- **Suggested command:** `/normalize`

**[P2] Two conflicting visual languages (login vs app shell)**
- **Location:** `src/styles/components.css` `.lp-*` / `.main-wrapper` / `.role-btn` (sharp, `border-radius:0`, hard `box-shadow: 40px 40px 0`) vs `.shell`/`.card`/`.btn` (rounded `radius-sm`/`radius-pill`, soft shadows)
- **Category:** Anti-Pattern / Consistency
- **Impact:** A user signing in meets a neo-brutalist, hard-edged aesthetic, then lands in a soft, rounded, teal app. The jarring hand-off undermines brand coherence and feels like two products.
- **Recommendation:** Unify on one language. Either soften the login (rounded inputs, brand shadow) or intentionally justify the split (e.g. "institution/portal" vs "workspace"). At minimum match radius + shadow tokens.
- **Suggested command:** `/normalize` (or `/critique` for the decision)

**[P2] Redundant `--primary` ≡ `--accent`**
- **Location:** `src/styles/tokens.css:42-53`
- **Category:** Theming
- **Impact:** `--primary` and `--accent` are **both `#01796F`**. The distinction is meaningless, which is why dark-mode contrast bugs surfaced (the single teal is overloaded for both bg and fg). Confuses future theming.
- **Recommendation:** Give `--accent` a distinct role (e.g. a brighter/interactive teal) or collapse to one token.
- **Suggested command:** `/normalize`

**[P2] Button-variant duplication / weak primary signal**
- **Location:** `src/styles/components.css:110-176`
- **Category:** Anti-Pattern
- **Impact:** `.btn-outline` and `.btn-secondary` are near-identical (transparent + border + ink). `.btn-accent` uses `--ink-muted` (gray) which reads as *disabled/secondary*, muddying which action is primary. Risk: users can't tell the main CTA.
- **Recommendation:** Keep one outline/secondary; make the true primary unmistakable (teal fill, per `.btn-primary`). Avoid gray for an "accent" action.
- **Suggested command:** `/normalize`

## Patterns & Systemic Issues

1. **Tokens are defined but not enforced.** A real token system exists and is largely followed — yet undefined tokens ship silently (CSS doesn't error). This is the single highest-leverage fix: add a token-lint/CI check so `--text-2sm`/`--text-1`/`--hover-bg`/`--success-light` can't slip through.
2. **Dark mode is reactive, not token-driven.** It's a 500-line sheet of per-component `!important` patches rather than flipped token values. Every new component must be manually dark-patched or it breaks contrast.
3. **Semantics are uneven across pages.** `student-dashboard.jsx` is clean (3 onClick / 3 button, 8 aria, `role=` present), but the repo-wide 265 `onClick` vs 65 `<button` means other pages likely use clickable divs without `role`/`aria`. A11y quality is inconsistent.

## Positive Findings (keep these)

- **Coherent, non-AI brand:** Pine-teal + serif accent + section-type hues. Intentional, memorable.
- **Real responsive system:** 5 breakpoints, mobile bottom-nav, fluid `clamp()` type, `prefers-reduced-motion` honored, 44px+ touch targets throughout.
- **Accessibility bones are good:** `:focus-visible` rings on buttons/tabs/inputs, `min-height:44px` targets, `content-visibility:auto` for render perf, `env(safe-area-inset-*)` for notches.
- **Performance-aware:** off-screen sections use `contain-intrinsic-size`; transitions use transform/opacity, not layout props.
- **Dark mode exists and is wired** (`App.jsx:244` toggles `data-theme`) — rare for a codebase this size.
